# Phase 17 - UI Design Contract

> Visual and interaction contract for the Library Catalog: the File menu entry and its update count, the non-modal catalog window (search, list, detail pane, job strip), the four statuses and the two problem rows, the Add flow (licence page, Add preview), Add by URL, the Update preview, the Remove confirmation, Reinstall, the busy and refusal rules, the log lines and the User Guide page. Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> This is a **PySide6 / Qt Widgets desktop app**, not a web frontend. There is no CSS framework, shadcn or Tailwind. Values are in Qt terms (px at 96 DPI, `QFont` point sizes, colour tokens from `kicad_lib_manager/widgets/theme.py`). Behaviour decisions come from `17-CONTEXT.md` (D-01..D-28, locked); they are not re-opened here. This file adds the visuals and copy that CONTEXT left to Claude's discretion. A choice made here rather than locked upstream is marked **(default)**. The owner is not a designer and was not asked questions: every UI-related "Claude's Discretion" item in CONTEXT is resolved in "Resolved discretion items" below.
>
> The v1.0 base contract that 15-UI-SPEC.md cites is no longer in this repository. Its tokens, glyph set, log routing and dialog rules are taken from `15-UI-SPEC.md` (approved 2026-11-23) and from the code (`theme.py`, `log_panel.py`, `help_dialog.py`, `import_result.py`, `scan_progress.py`, `main_window.py`). Everything 15-UI-SPEC.md declares (theme tokens, glyph set, 28 px minimum control height, window-modal question rule, back buttons named for where they go, "no QMessageBox except the sanctioned confirms") applies here unchanged and is only restated where this phase uses it.
>
> **Plain-language rule (owner feedback, binding):** no field name of the catalog record, no git command or option name, no SPDX code, no Python identifier appears in user-facing text. Values the user has to recognise stay: KiCad path variables such as `WE_3DMODEL_DIR` and `${KICAD_LIB_GITHUB}`, folder paths, library names, a short commit id, the file name `catalog.json` where the user must commit it.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native Qt Widgets; no web design system, no shadcn) |
| Preset | not applicable |
| Component library | Qt Widgets via PySide6 6.12.0 (native Windows style; local stylesheet strings only where listed) |
| Icon library | none. Text glyphs only, always in the text colour of the row: `⚠` warning, `✖` error, `✓` success, `✕` dismiss. No image assets, no emoji font. **No new glyph is added in this phase.** |
| Font | System UI font at the platform default size (Segoe UI 9pt on Windows 11); `Consolas` 9pt for folder paths, commit ids, path variable names and licence file text (same as `LogPanel` and the library-folder row). |

Reused without change (do not re-specify, do not contradict):

- `kicad_lib_manager/widgets/theme.py`: `AMBER`, `AMBER_TINT`, `ERROR`, `SUCCESS`, `ACCENT`, `LINK`, `MUTED`, `SURFACE`, `SURFACE_HEADER`, `BORDER`, `SP_XS..SP_XL`, `HEADING_PT`, `MONO_FAMILY`, `MONO_PT`, `PRIMARY_BUTTON_QSS`. **No new constant is added to `theme.py` by this phase.** The one new stylesheet (the destructive confirm button) is composed locally from the existing `ERROR` constant.
- `ElidedLabel` (`widgets/import_result.py`, `set_full_text`, `ElideMiddle`, `full_tooltip=True`) for every path that can be long. If importing it creates a cycle, move it to its own small module in `widgets/`; do not write a second elision widget (same rule as Phase 15).
- `centre_window` (`widgets/import_dialog.py`) to place the catalog window over the main window before its first show, and again once shown (same as the User Guide).
- `run_in_background` / `TaskWorker` patterns for every check that can block (free space on a network drive, KiCad-open check); no filesystem or network call runs on the GUI thread.
- The main window's `_question` and `_confirm_path_var_changes` for the path variable confirmation, and its KiCad-open three-button variant (`Retry` / `Change anyway` / `Not now`). They are reused as they are; the catalog adds no second confirmation for path variables.
- `LogPanel` levels `info`, `warning`, `error`, `success`. No new level.
- The amber strip look of `checkoutBanner` (`AMBER_TINT` fill, 2px `AMBER` left bar, `⚠` glyph) for the Git-version strip.
- The collapsed list pattern of the Import Result view: a list of more than 3 entries starts collapsed behind a `Show` toggle, the heading keeps the count.

## Spacing Scale

Declared values (multiples of 4), the existing `theme.py` tokens; no new token.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between a glyph and its text; gap between rows inside a strip; gap between a detail label and its value. |
| sm | 8px | `setSpacing` for every new layout; gap between the search box, `Check for Updates` and `Add by URL...`; gap between buttons; gap between form rows; splitter handle height. |
| md | 16px | Window `setContentsMargins` (all four sides); inner margins of the detail pane and of each review page; gap between the sections of a review page. |
| lg | 24px | Gap between the page heading and the first section of a review page. |
| xl | 32px | Not used. |
| 2xl / 3xl | 48px / 64px | Not used (desktop window). |

Layout rules:

- Catalog window: default size 900 x 640, minimum size 760 x 520, centred over the main window, size not persisted **(default)** (same rule as Phase 15 dialogs). One window only: the menu action opens it when closed and raises it when open.
- Window layout, top to bottom: header row, notice strips (only when shown), toolbar row, splitter (list above, detail pane below, initial split about 45% / 55%, list minimum 120 px, detail pane minimum 200 px), job strip (only while a job runs), button row with `Close`. Margins 16, spacing 8.
- Detail pane: `SURFACE` fill, 1px `BORDER`, internal margins 16, spacing 8; its pages sit inside a `QScrollArea` with no frame. Review pages: sections 16 apart, a heading and its first row 24 apart.
- Notice strips and the result strip: internal margins 8, spacing 4, 1px `BORDER` frame, or the amber 2px left bar form for warnings.
- Interactive controls (line edits, buttons) have a minimum height of 28px (Phase 5 rule). List rows use the platform default row height.
- Nickname and file lists inside review pages: at most 6 rows tall (about 144 px), then they scroll on their own; they never push the primary button off the page.

Exceptions: 1px and 2px borders are outlines, not spacing. The 2px left bar on a warning strip matches the existing `checkoutBanner`. No new layout value below 4 or off the 4-multiple scale.

## Typography

Declared in points (Phase 5 rule). **Two point sizes in use (9pt and 10pt), with the 9pt body size also used for the monospace face: three text styles (Body, Heading, Mono), two weights (400, 700).** `DISPLAY_PT` (12) exists in `theme.py` and is not used by this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (list cells, labels, field text, buttons, hints, strips, menu text, status cells) | 9pt (system default; do not call `setPointSize`) | Regular 400 | Native single-line metrics; 1.5 for wrapped blocks (strips, the page bodies, the Remove explanation) |
| Heading (window heading, detail pane library name, review page heading) | 10pt (`HEADING_PT`) | Bold 700 | 1.2 |
| Mono (every folder path, commit id, path variable name, the licence file text, the `.gitignore` line) | 9pt `Consolas` | Regular 400 | 1.2 |

Hints and secondary text use Body size in `MUTED`, never a fourth size. Bold at Body size appears only on the text of a `PRIMARY_BUTTON_QSS` button and of the destructive confirm button (both already bold by their stylesheet). Library names, nicknames and licence names stay in Body (as in the main window's trees); only paths, ids and path variable names are Mono.

Links use `LINK`, not the accent. The selected list row uses the platform selection colour. The first accent button in the main window and the one in the catalog window can be on screen together because the windows are separate; each window has at most one.

Semantic colours:

| Meaning | Colour | Elements |
|---------|--------|----------|
| Needs attention / warning | `AMBER #8A5200` (strips on `AMBER_TINT #FFF8E1`) | `⚠ Update available`, `⚠ Problem: not in the catalog`, the Git-version strip, share-alike / proprietary / not-stated licence notes, "removed" nicknames in the Update preview, name clash rows, the KiCad-open line, a path variable that is not set, `Severity.WARNING` log rows |

### The list (D-16, CAT-01)

One row per library. Columns, left to right: **Name** (stretch), **Status** (fixed 200 px), **Licence** (fixed 120 px), **Size** (fixed 80 px, right-aligned). Rows are sorted by Name, case-insensitive, and never reorder when a status changes **(default)**. Single selection, full-row selection, keyboard navigable (Up / Down, Home / End). Accessible name `Libraries`. Header clicks do nothing.

Which rows exist: every curated library (installed or not), every library in the catalog record that is not curated (added by URL), and every folder in `ThirdParty/` that the record does not list (except `.staging`, which is never shown).

Status cell, exactly one of:

| Status | Cell text | Colour | Detail pane strip and buttons |
|--------|-----------|--------|-------------------------------|
| Not installed | `Not installed` | `MUTED` | Buttons: `Add This Library` (primary) |
| Installed, confirmed current | `✓ Installed` | `SUCCESS` | Buttons: `Update This Library` (disabled, tooltip `Already up to date.`), `Remove This Library` |
| Installed, not checked or could not be checked (offline) | `Installed` (no glyph) | `MUTED`, tooltip `Updates have not been checked, or GitHub could not be reached.` | Buttons: `Update This Library` (disabled, tooltip `No update is known. Press Check for Updates.`), `Remove This Library` |
| Update available | `⚠ Update available` | `AMBER` | Strip `⚠ A newer version is available ({installed} -> {available}).` Buttons: `Update This Library` (primary), `Remove This Library` |
| Problem: folder missing (D-05) | `✖ Problem: folder missing` | `ERROR` | Strip (below). Buttons: `Reinstall This Library` (primary), `Remove This Library` |
| Problem: not in the catalog (D-06) | `⚠ Problem: not in the catalog` | `AMBER` | Strip (below). Buttons: `Remove This Library` only |

Problem strips (top of the detail page, `✖` in `ERROR` for the first, `⚠` in `AMBER` for the second):

- Folder missing: `✖ The folder {folder} is missing. It may have been deleted, or this collection was copied from another computer without it. Reinstall This Library downloads it again from {repository}.`
- Not in the catalog: `⚠ This folder is in ThirdParty but is not in the catalog, so the app does not know where it came from. Its libraries are still scanned like any other. The app never deletes it by itself; Remove This Library deletes it after you confirm.`

Licence cell: the display names of "Licence labels" (`CC BY 4.0`, `MIT`, `Proprietary`, `Not stated`, `Unknown`). Size cell: `{n} MB` below 1000 MB, `{x.x} GB` from 1000 MB, `Unknown` (`MUTED`) when no size is known. Name cell: the curated friendly name, or `{owner}/{repo}` for a library added by URL, or the folder name for a problem row not in the catalog.

Row text is elided at the cell width with the full text as tooltip. Search: case-insensitive text match on Name, description and repository; rows that do not match are hidden; an empty search shows all. Selection is kept when the row still matches, otherwise the detail pane shows its empty state.

**Details page** (default). Heading = library name (Heading). Under it a Body `MUTED` one-line description for curated libraries. An optional result strip (below). Then labelled rows (label left in Body, value right; label column 120 px, value wraps):

### Add flow (CAT-02, CAT-08, D-04, D-10, D-13..D-15, D-18, D-20)

Pages inside the detail pane. The list is locked to the chosen library while a page is open.

```
Details (not installed)            Licence page                    Add preview
 [Add This Library] ---------->  [Back to List] [Download and Check] ---> [Discard Download] [Add Library]
                                       (nothing written)         (staging download   (renames into place,
                                                                  runs here, job strip)  writes catalog.json)
```

**1. Licence page** (before anything is downloaded). Heading `Add {name}`. MUTED body `Read the licence before you download. Nothing is added to your collection yet.` Rows: Repository (link), Licence (display name), Size, `Will be installed in` (ElidedLabel, Mono, `{collection}/ThirdParty/{id}`; the id is the curated id, or `{owner}-{repo}`).

- Licence note by class (below the Licence row, one line, wraps):
  - Open: no note.
  - Share-alike: `⚠ Share-alike licence: if you share changed copies of these files, you must share them under the same terms.`

For a not-stated or unknown licence it does not appear here (it appears on the Add preview). Never pre-ticked. A Reinstall page shows `You confirmed the licence terms on {date}.` instead of the tick.
- Refusal rows (each `✖`, stops the page; `Download and Check` disabled, only `Back to List` remains):
  - Not enough free space (D-15): `✖ There is not enough free space on {drive} for {name}. It needs about {size} plus a safety margin of {margin}, and {drive} has {free} free. Free some space, then try again.` Unknown size: no check, no row.
  - Already in the catalog (Add by URL): `✖ This library is already in your catalog as {name}. Select it in the list.`
  - Folder exists but is not in the catalog (D-06): `✖ The folder {folder} already exists in ThirdParty but is not in the catalog. Remove it first (it is listed as "Problem: not in the catalog"), then add the library again.`
- KiCad-open line (D-14, `⚠` AMBER, not a refusal): `⚠ KiCad is open ({names}). Restart it after the library is added to see the changes.` Detected off the GUI thread; shown when the page opens, never blocks.
- Buttons (right, bottom): `Back to List` (plain), `Download and Check` (primary; `Ctrl+Return`). On press the page stays, the buttons disable and the job strip starts (`Downloading {name}...`).

**2. Add preview** (after the staging download and its checks). Heading `Add {name}`. A `✓` line: `✓ Downloaded and checked: {s} symbol libraries and {f} footprint libraries.` Then sections 16 px apart (each section is a bold-free label row in Body; there is no sub-heading style):

1. `What will be added`: a Mono block, one row per item:
   - `{collection}/ThirdParty/{id}/` followed by `{s} symbol libraries, {f} footprint libraries` (Body, `MUTED`).
   - `{collection}/catalog.json` followed by `records this library`.
   - Only when the root is a git repository and `.gitignore` lacks the line: `{collection}/.gitignore` followed by `gets the line /ThirdParty/ so git does not treat the downloaded libraries as part of your collection` (when the file does not exist: `is created with the line /ThirdParty/ ...`).
2. `Path variables` (only when the library needs some): `This library needs the KiCad path variable {VAR} to point to {folder}. After you press Add Library, the app asks before it changes KiCad's settings.` One line per variable if several.
3. `Libraries with the same name` (D-20, always present):
   - None: `✓ No library has the same name as one you already have.`
   - Some: an amber `⚠ {n} libraries have the same name as a library you already have:` then a 3-column list (Library, Kind: `Symbol` / `Footprint`, `Same name as`: `a KiCad library`, `{catalog library name}`, `your Atomic_ libraries`, `your Custom libraries`), then a MUTED line `They start unticked, so Generate Tables will not list two libraries with one name. Tick one yourself if you want it. Names are never changed.`
4. `Licence` (only when it was not known on the licence page): the licence file text in a read-only Mono box (8 lines, scrolls), then the tick `I have read the licence terms`. A repository with no licence file at all shows `⚠ This repository has no licence file, so nothing says what you may do with it.` and the same tick. The tick disables `Add Library` until ticked. When the licence was settled on the licence page this section is a single line: `Licence: {name}` (plus `(you confirmed you read the terms)` after a tick).
5. KiCad-open line as above, when KiCad is open.

Buttons: `Discard Download` (plain; deletes the downloaded copy, returns to the list; tooltip `Delete the downloaded copy. Nothing is added.`) and `Add Library` (primary; `Ctrl+Return`). While the rename and the record write run (a few seconds) the buttons disable and the job strip reads `Adding {name}...`.

**3. Refusal after the download** (Git LFS (D-13), not KiCad, KiCad 5 only, Plugin and Content Manager only, an unreadable or oversized library, a failed download). The page shows the matching `✖` row (copy below) and `Nothing was added. The downloaded copy was deleted.`; buttons `Back to List` and, for a failed download only, `Try Again` (primary).

**4. After a successful Add (D-18).** Sequence the user sees, in order:
1. The Details page shows the library as `✓ Installed` with the result strip `✓ Added {name}: {s} symbol libraries and {f} footprint libraries are in your scan.`, plus (clashes) `⚠ {n} of them share a name with a library you already have and are unticked.`
2. The main window rescans that one source (the existing per-source rescan; no Loading Libraries window). Its libraries appear in the main window ticked, except the clashing ones.
3. If the library needs path variables, the existing `Change KiCad path variables?` question opens over the **main window** (window-modal, `No` default, three-button variant when KiCad is open). Declining logs the existing `info` line. Nothing is written without `Yes` or `Change anyway`.
4. The result strip's `Generate Tables` button stays available; it runs the main window's Generate Tables with the current selection (the user starts it; nothing runs by itself).

While steps 2 and 3 run, every action button in the catalog window is disabled with tooltip `Finishing the last change...`, and a folder switch is refused (see Busy rules).

### Update flow (CAT-04, D-07, D-08, D-09)

`Update This Library` (primary on the Details page of a library with an update). Per library only; there is no `Update all` (D-09).

2. **Dirty folder (D-07).** If files in the folder were changed, the page shows `✖ {name} cannot be updated: files in {folder} were changed after it was added. Catalog libraries are managed copies, and an update would overwrite your changes. Keep your own changes in Custom/ instead.` and below it the changed files in Mono, at most 8 rows then `and {n} more`. Buttons: `Back to List`.
3. **Update preview (D-08).** Heading `Update {name}`. Rows:
   - `Version`: `{old short commit}  ->  {new short commit}` in Mono.
   - `Files changed`: `{n} files`.
   - `Libraries added ({n})`: names in a list (collapsed behind `Show` above 3). `None` when zero.
   - `Libraries removed ({n})`: names in `AMBER` with `⚠`, same collapse rule, then the MUTED line `Projects that use a removed library lose those parts.` `None` when zero.
   - KiCad-open line when KiCad is open.
   - Buttons: `Keep Current Version` (plain; tooltip `Do not update. Nothing changes.`) and `Update Library` (primary).
   - Already current by the time of the check: `✓ {name} is already up to date.` with `Back to List`.
4. After `Update Library`: job strip `Updating {name}...`, then the Details page with the result strip `✓ Updated {name} to {short commit}: {a} libraries added, {r} removed.` and the `Generate Tables` button; the main window rescans that source (libraries that stay keep their tick; new ones are ticked like after an Add, except clashing ones, which are unticked **(default)**).

### Remove flow (CAT-04, D-21, D-06, D-05)

`Remove This Library` on the Details page (plain; its confirm button is `Remove Library`, so the two labels differ). A confirmation page replaces the Details page. No accent button on this page.

Heading `Remove {name}?`. Body rows:

- `This deletes the folder {folder} ({size} on disk) and removes {name} from the catalog.` (folder gone already: `The folder is already gone, so only the catalog entry is removed.`)
- `Libraries that leave your scan ({n})`: the nicknames, collapsed behind `Show` above 3; then `The next Generate Tables drops them from your KiCad library tables.`
- `Path variables it used`: `{VAR}` list in Mono, then `They stay set in KiCad. Projects that still use this library's 3D models lose them.` (none: omit the row).
- KiCad-open line when KiCad is open.
- Buttons: `Keep Library` (plain, **the default button**, `Esc` = this) and `Remove Library` (destructive: fill `ERROR`, white text bold, same padding and minimum height as `PRIMARY_BUTTON_QSS`, composed locally; never the default; no `Ctrl+Return`).

During the delete the job strip reads `Removing {name}...` (indeterminate) with `Cancel Removing` disabled and tooltip `Removing cannot be stopped halfway. It ends in a moment.` After it: the row leaves the list (or returns as `Not installed` for a curated library), the result strip `✓ Removed {name}. Press Generate Tables to drop its libraries from your KiCad library tables.` and the main window rescans. A deleted `Problem: not in the catalog` folder disappears from the list.

### Reinstall flow (D-05, D-18)

`Reinstall This Library` (primary, on a `Problem: folder missing` row) follows the Add flow with these differences: the licence page heading is `Reinstall {name}`, shows the recorded repository and branch, shows `You confirmed the licence terms on {date}.` instead of the tick, and its primary is `Download and Check`; the preview heading is `Reinstall {name}` and its primary is `Reinstall Library`. The preview's `What will be added` row lists only the folder (the record already exists; it is updated with the new commit). After success the same three follow-ups as an Add run (rescan of the source, path variable question, `Generate Tables` offer).

### Job strip (D-16)

Visible only while a job runs, between the splitter and the button row. One row: a Body label with the current step (left, stretch), a `QProgressBar` (fixed 240 px wide, accessible name `Progress of {job}`), and a plain cancel button whose label names the job (`Cancel Adding`, `Cancel Updating`, `Cancel Reinstalling`, `Cancel Check` for a repository check, `Cancel Removing`); the word Cancel stays, as D-16 names it, and the noun says what is stopped. The tooltip reads `Stop {job label} and delete what it downloaded. Nothing is changed.`

| Job | Label steps | Cancel button |
|-----|-------------|---------------|
| Check repository | `Checking the repository...` (indeterminate) | `Cancel Check` |
| Add | `Downloading {name}... {n}%` (determinate when the percentage is known, else indeterminate), `Checking {name}...`, `Adding {name}...` | `Cancel Adding` |
| Update | `Looking for changes in {name}...`, `Updating {name}...` | `Cancel Updating` |
| Reinstall | `Downloading {name} again... {n}%`, `Checking {name}...`, `Adding {name}...` | `Cancel Reinstalling` |
| Remove | `Removing {name}...` (indeterminate) | `Cancel Removing` (disabled) |
| Check for updates (startup or manual) | no strip; the toolbar button reads `Checking...` and the Details page `Updates` row reads `Checking for updates...` | none |

The cancel button stops the job and deletes what it made: the label becomes `Stopping...`, the button disables, and when the job ends the log gets one `info` line (Copywriting) and the page returns to where the user started (the list for an Add, the Details page for an Update). Nothing in the collection changes.

### Close rules (D-16)

- Idle: `Close`, `Esc` and the window's close box close the window. The window is hidden, not destroyed, so reopening it is instant and its search text is cleared **(default)**.
- A job runs (Add, Update, Reinstall, Check repository): closing opens the window-modal question over the catalog window. Title `Stop the current job?`; text `{Job label} is still running. If you close the catalog now, it is stopped and the partly downloaded files are deleted. {Consequence}` where the consequence is `Nothing is added to your collection.` (Add, Reinstall), `{name} stays on the version it has now.` (Update) or `Nothing is changed.` (Check repository). Buttons `Stop and Close` and `Keep Working` (the default and the `Esc` button). `Stop and Close` runs the same code as the cancel button and closes the window when the job has ended.
- A Remove runs: closing is ignored and the job strip label reads `Removing cannot be stopped halfway. Close this window after it ends.` for as long as it runs. No dialog.
- A download is waiting on the Add preview or the Update preview: closing asks nothing; the window closes and the downloaded copy is deleted (same as `Discard Download`), logged `info` `Discarded the download of {name}. Nothing was added.`
- Closing the main window closes the catalog window first through the same rules; if the user picks `Keep Working`, the main window stays open too.
- The window and its workers follow the same close rule as the migration dialog's timers: nothing a timer or worker starts after the window closed (no worker survives `done()`).

### Busy rules (D-16, D-14)

The catalog's action buttons (`Add This Library`, `Update This Library`, `Reinstall This Library`, `Remove This Library`, `Add by URL...`, `Check for Updates`, `Set Path Variables...`, and every primary and confirm button on a page) are disabled, each with the reason as tooltip, while:

| Condition | Tooltip |
|-----------|---------|
| A scan runs in the main window | `Wait for the scan in the main window to end.` |
| The import window is open or an install is pending | `Close the import window first.` |
| The migration window is open | `Close the migration window first.` |
| Another catalog job runs | `Wait for {job label} to finish.` |
| The last change is still finishing (rescan, path variable question) | `Finishing the last change...` |

Browsing (search, selecting, reading details, `Help`, `Close`) always works.

The folder switch of the main window (Open, Recent, Use KiCad's Folder, Change Folder..., New Library Collection...) is **refused** while a catalog job runs, a downloaded copy waits for an answer on a review page, or the last change is finishing. The refusal changes nothing, writes one `warning` log line and one 5000 ms status bar message with the same text (no dialog), same mechanism as the import window's refusal:

- Job running: `The library folder cannot change while the library catalog is working. Wait for it to finish, or stop it with the cancel button in the catalog window.`
- Download waiting: `The library folder cannot change while a downloaded library waits for your answer in the catalog window. Press Add Library or Discard Download there first.`

An idle catalog window (list or details only) never blocks a switch; when the folder changes it reloads for the new collection at once (header path, list, statuses, an update check for the new collection starts) and any open page without a download is dropped.

### Update check at startup (CAT-07, D-12, D-19)

No dialog, no progress, no blocking. After the first scan ends, one background check per installed library runs. Outcomes:

- At least one update: one `info` log line `2 catalog libraries have updates: SparkFun, Espressif` (singular `1 catalog library has an update: SparkFun`; with more than 4 names, the first 4 then `and {n} more`) and the menu text with the count.
- No update, offline, or a collection with no installed libraries: **no line** and no change to the menu text. The Details page `Updates` row says `Could not check for updates (GitHub could not be reached)` for an offline result.
- The manual `Check for Updates` writes one `info` line: the same summary when there are updates, else `Checked {n} catalog libraries: all up to date.`; when offline, `Could not check for updates: GitHub could not be reached.` (`warning`).

### Keyboard, focus and accessibility

- Every input has an accessible name equal to its visible label or placeholder: `Search libraries`, `Web address`, `Libraries` (list), `I have read the licence terms`, `Progress of {job}`.
- Status text is the cell text itself (glyph plus words), so a screen reader reads `Update available` once; glyph-only controls: none are added.
- Result and refusal rows are plain labels with `setAccessibleName` set to their full text.
- No shortcut beyond `Ctrl+Shift+L` (menu), `F1` and `Ctrl+Return` (catalog window). Menu mnemonic as in the menu table.
- Focus after a page change: the page's first input (URL field, the tick when present, else the primary button); after returning to the list, the list row that was selected.

## Settings and Persistence (UI side)

No new `QSettings` key **(default)**.
