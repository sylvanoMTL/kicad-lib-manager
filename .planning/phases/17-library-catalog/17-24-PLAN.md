<objective>
D-33's naming part, as decided in D-34: catalog libraries from KiCad's add-on list (and any library whose own links use them) get KiCad's add-on names, `PCM_<name>`, so links between add-on packages resolve, without breaking a library whose git copy links its own plain names; the rule is recorded and applied by every scan; and the catalog keeps away from what KiCad's own add-on manager owns.

Research done for this plan (KiCad source, 9.0 branch, `eeschema/symbol_lib_table.cpp` and `kicad/pcm/pcm_task_manager.cpp`; 4ms's README and `PCM/make_archive.sh`):
- KiCad's manager unpacks a package into `${KICAD<n>_3RD_PARTY}/<symbols|footprints|3dmodels>/<identifier with dots as underscores>/` (default `<Documents>/KiCad/<version>/3rdparty`), and at every load of the global tables adds a row per library: nickname = the `pcm.lib_prefix` setting (default `PCM_`) + the file or folder stem (`_1`, `_2` appended when the name is taken), URI `${KICAD<n>_3RD_PARTY}/symbols/<pkg>/<file>`, description "Added by Plugin and Content Manager"; it removes rows under that folder whose file is gone.
- Package authors write the literal `PCM_` into their files: 4ms's `make_archive.sh` rewrites `4ms_X:` to `PCM_4ms_X:` and `${KICAD_4MS_LIBS}/3dmodels/` to `${KICAD<n>_3RD_PARTY}/3dmodels/<pkg>/` when it builds the zip, so 4ms's git repository keeps plain names (its README: keep the nicknames unchanged; the git and add-on copies use different names). Espressif's git repository already links `PCM_Espressif:`.
- Decision (D-34): the catalog uses the literal `PCM_` (never reads KiCad's setting), decides per library from its own links, sets no `KICAD<n>_3RD_PARTY` (the manifest rules already refuse `*_3RD_PARTY`), and lets the table merge keep any row KiCad's manager wrote. KiCad gives its own copy a `_1` name when the catalog's row came first.

Purpose: D-33, D-34 (names follow each library's own links), CAT-05 (the libraries appear in the scan and in Generate Tables), CAT-08 (names never changed by a clash), CAT-10 (KiCad's add-on manager left alone), CAT-06 (no variable of KiCad's manager is set), D-20, D-28 (Würth keeps its names).
Output: the record fields, the rule in the staging check, the scan, the workers, tests.
</objective>
