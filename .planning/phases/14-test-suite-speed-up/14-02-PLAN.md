<objective>
Mark every real-git test `slow` and add a runtime tripwire so a future unmarked git test fails loudly instead of silently slowing the quick run.

Purpose: TEST-06 (slow tests carry the marker, strict markers on) and the quick-run half of TEST-04 (the GSD gate fits 600 s only when the git tests leave the default run). CONTEXT "What counts as slow" asks for real git repos or submodules, the Wurth corpus and kicad-cli; the Wurth and kicad-cli part landed in 14-01. The tripwire makes the git part exhaustive without guessing.
Output: tripwire in tests/gitfixtures.py fed by a conftest hook, `slow` marks in the twelve modules that use the git builders, and `slow` marks on the two tests in tests/test_atomic_uat.py that run their own `git init` (the builder tripwire cannot see those; plan 14-04's static `@requires_git` audit and its runtime subprocess watch, which fails any unmarked test that runs `git init`, `git clone` or `git submodule add|update --init`, are what fail a future unmarked one).

The tripwire and the marks land in the same plan on purpose: the post-merge test gate runs after this wave, and a tripwire without the marks would fail about 190 tests.
</objective>
