Facts the docs describe (from 14-01..14-05; check each against the code before writing it down):
- `--full` (tests/conftest.py) clears the default `-m 'not slow'`; Windows PowerShell 5.1 drops `-m ""`, so `--full` or `-m "slow or not slow"` are the safe spellings (RESEARCH Pitfall 2).
- Slow = creates a real git repository (through the gitfixtures builders or its own `git init`, `git clone` or submodule clone), `wurth`, `kicad_cli`, the `kicad_cli_path` fixture, or among BASELINE.md's 50 slowest. Builder tripwire (14-02, fails before any git work): `<nodeid> builds a real git repository: mark it @pytest.mark.slow`. Subprocess watch (14-04, fails the test at teardown, with or without `@requires_git`): `<nodeid> creates a real git repository (<command>): mark it @pytest.mark.slow`, where the command is `git init`, `git clone`, `git submodule add` or `git submodule update --init`.
- Running a module whose tests are all slow without `--full` ends with "no tests ran" (exit 5); the GSD regression gate can hit this when the prior-phase test files are all slow (RESEARCH Pitfall 8): document, do not work around.
- Timeout 300 s per test, thread method; under workers a timeout's failure report reads `TIMEOUT <nodeid> after <N> s: pytest-timeout ended the worker (rerun with -n 0 to see its stack dump)` above xdist's `worker 'gwN' crashed while running '<nodeid>'` (14-01 conftest hooks; a crash without that first line is a real crash, not a timeout); rerun with `-n 0 --timeout=<s>` for pytest-timeout's own "Timeout" banner and the stack dump (RESEARCH Pitfall 3). `test_wurth_corpus_parse_budget` has 900 s.
- `--pdb`, `-s` and `breakpoint()` need `-n 0` (RESEARCH Pitfall 11).
- Without pytest-xdist installed, pytest stops with "unrecognized arguments: -n": install with `.\env\Scripts\python.exe -m pip install -r requirements-dev.txt`.
- Isolation: every test gets its own empty user folders (APPDATA, LOCALAPPDATA, USERPROFILE, HOME, XDG_CONFIG_HOME, XDG_DATA_HOME) and QSettings ini; KICAD_LIB_GITHUB, CUSTOM_3DMODEL_DIR and WE_3DMODEL_DIR are removed; KICAD_CONFIG_HOME points at the test's own folder, so kicad-cli reads and writes its config there; a test that needs another value sets it with monkeypatch.
- Test dependencies: install with `.\env\Scripts\python.exe -m pip install -r requirements-dev.txt` in the venv you run tests from; the main checkout's venv is the app's runtime venv and gets them only when tests are run there (CONTEXT "Orchestrator decisions after research (2026-11-22)", venv install).
- Run-level guards: `the test run changed the real app state: <paths>` fails the run; `warning: KiCad's own config changed during the run (was KiCad open?): <paths>` only warns; `the test run changed the live Custom/ folder: <paths>` fails the run in any worker. Rerun after using the app, KiCad or editing Custom/ during a run.
- The `local_kicad` tests are opt-in (14-05; RESEARCH Open Question 1, RESOLVED as the strict reading): without `KICAD_TEST_REAL_CONFIG=1` they collect as one item skipped with "reads your real KiCad config tables: set KICAD_TEST_REAL_CONFIG=1 to run" and nothing reads the real KiCad config, also not at collection; with it they read the owner's KiCad tables read-only (and skip with "no KiCad user config tables found" when there are none). No test reads the real KiCad config in a default run.
- Git templates: built once per run in the pytest base temp under a lock, removed at the end; old `gitfixture_template_*` folders in %TEMP% from runs before this phase can be deleted by hand (the tests never delete them).
- `--basetemp` only as a one-off (for example a short path), never in addopts: pytest wipes it at start, so two runs at once would destroy each other.
