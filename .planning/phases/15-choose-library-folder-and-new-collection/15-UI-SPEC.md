# Phase 15 - UI Design Contract

> Visual and interaction contract for the library-folder display, the File menu actions, the first-run window, the Open Library Collection window, the New Collection dialog, the busy refusals, the commit panel without a parent option and the post-switch KiCad path variable offer. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This is a **PySide6 / Qt Widgets desktop app**, not a web frontend. There is no CSS framework, shadcn or Tailwind. Values are in Qt terms (px at 96 DPI, `QFont` point sizes, hex colors through `theme.py`). Behaviour decisions come from `15-CONTEXT.md` (locked) and the owner's earlier decisions D3 and D4; they are not re-opened here. This file adds the visuals and copy that CONTEXT left to Claude's discretion. A choice made here rather than locked upstream is marked **(default)**. The owner is not a designer and was not asked questions: every Claude's Discretion item in CONTEXT is resolved in the section "Resolved discretion items" below.
>
> The existing Phase 5 contract (`milestones/v1.0-phases/05-import-ui-and-post-install/05-UI-SPEC.md`) is the base. Everything it declares (theme tokens, spacing, typography, glyph set, log routing, window-modal rule, "no QMessageBox except the sanctioned confirms") applies here unchanged and is only restated where this phase uses it.

## Spacing Scale

Declared values (multiples of 4), the existing `theme.py` tokens; no new token.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between a result glyph and its text; gap between an option title and its description. |
| sm | 8px | `setSpacing` for every new layout; gap between the label, path, tag and button in the library-folder row; gap between form rows; gap between check rows. |
| md | 16px | Dialog `setContentsMargins` (all four sides); inner margins of an option row; gap between dialog sections. |
| lg | 24px | Gap between the heading block and the first option row in the first-run window. |
| xl | 32px | Not used. |
| 2xl / 3xl | 48px / 64px | Not used (desktop dialogs). |

Layout rules:

- First-run window: `setContentsMargins(16, 16, 16, 16)`, `setSpacing(8)`, fixed width 560, height from content, centered on the primary screen. Option rows are 560 - 32 = 528 wide with internal margins 16 / 8 (left-right / top-bottom) and 8 between the text block and the button.
- Open Library Collection and New Collection dialogs: same margins and spacing, minimum width 560, height from content, centered over the main window (over the first-run window when opened from it). Size is not persisted (**default**).
- The library-folder row: `setContentsMargins(0, 0, 0, 0)`, `setSpacing(8)`, minimum control height 28. It is the first item of the main window's central vertical layout, above the toolbar row, and the toolbar row is unchanged.
- Interactive controls (line edits, buttons) have a minimum height of 28px (Phase 5 rule).
- Folder check strip and notice strip: internal margins 8, spacing 4, 1px `BORDER` frame.

Exceptions: 1px and 2px borders are outlines, not spacing. The two-pixel left bar on a notice strip matches the existing `checkoutBanner`. The main window's existing toolbar spacing is untouched. No new layout value below 4 or off the 4-multiple scale.

#### Switch sequence (every way of switching, ROOT-03)

1. Refuse when busy (see "Busy refusals").
2. Run the folder check (off the GUI thread). For one-click sources (Use KiCad's Folder, Recent) a failed check is reported in the log (`error`) and the status bar for 5000 ms, and nothing changes. The Open Library Collection window shows it inline instead.
3. On pass: save the choice (`library/root`, and add to `library/recent`; **Use KiCad's Folder removes `library/root`** so the next start resolves to KiCad's folder again), update the title, the row and the menu, clear both trees (blank, no empty-collection message yet) and clear the selection. Selection starts fresh exactly as at app start (libraries already in the Destination tables are pre-selected); nothing is carried over from the previous folder.
4. Log `info`: `Library folder: {path} ({tag text without the warning part})`. If the path is longer than the threshold: also `warning`, see Copywriting.
5. Start a **full** scan (`_start_scan`, not the saved-scan shortcut): the existing Loading Libraries window appears. Each folder keeps its own saved scan; a switch never deletes one.
6. When the scan ends: fill the trees, or show the empty-collection message. Then the path variable offer, if it applies.
7. **Focal point after the change.** Once the scan has ended (and after the path variable question, when one was shown), keyboard focus goes to the **Symbols tree** with its first row current when the collection has libraries, so the user can start selecting at once. When the collection is empty, focus goes to the **Import Part...** button, which is the next step the empty-collection message names. After a first-run start the same rule applies to the first main window. The library-folder row itself never takes focus.

If the scan fails, the existing `Scan error: ...` log line appears and the row stays on the new folder with blank trees (the user can switch back through the same menu).

#### Empty collection

After a completed scan with **zero** symbol and zero footprint libraries, the list area shows one centered block instead of the two empty trees (a `QStackedLayout` page, planner's choice of mechanism): Heading `No libraries in this collection yet`, then a `MUTED` Body paragraph with the copy below. It disappears as soon as a scan finds a library. It is **not** shown before the first scan of a folder finishes, and not while a scan runs.

### Busy refusals (ROOT-03)

A switch is refused while: a scan is running, the import window is open or an install or its post-install work is pending, the migration window is open, or the KiCad path variable check is in flight. The disabled actions are the first line (they cannot be clicked); the handler **also** refuses when called programmatically (the Recent entries, `Change Folder...`, the first-run flow never run while busy). A refusal changes nothing, writes one `warning` log line and one 5000 ms status bar message with the same text. Texts in Copywriting. There is no dialog.

### Startup and fallback (ROOT-01, ROOT-02, ROOT-07)

Order is locked: `--library-root` > `KICAD_LIBMGR_ROOT` > remembered folder > `KICAD_LIB_GITHUB` > first-run window. Visual contract only:

| Situation at start | What the user sees |

### Post-switch KiCad path variable offer (ROOT-10)

Uses the **existing** `_sync_path_vars` / `_confirm_path_var_changes` machinery: the window-modal `Change KiCad path variables?` question listing `{VAR}: {old} -> {new}` lines (`KICAD_LIB_GITHUB`, `CUSTOM_3DMODEL_DIR`), default button `No`, and the three-button `KiCad is open` variant (Retry / Change anyway / Not now) when KiCad runs. When it is offered (all must hold):

1. A switch just completed (Open Library Collection, Recent, a first-run choice or a new collection), not a start with a remembered folder.

## Settings and Persistence (UI side)

| Key | Helper (new, in `settings.py`) | Use |
|-----|--------------------------------|-----|
| `library/root` | `load_library_root() -> Path \| None`, `save_library_root(path: Path)`, `clear_library_root()` | The folder the user chose. Saved on every successful Open / Recent / first-run / new collection switch; **removed** by Use KiCad's Folder. Never written by an override start. |
| `library/recent` | `load_library_recent() -> list[str]` (all saved entries, newest first), `add_library_recent(path: Path)` (max 10, newest first, no duplicates, like the Destination history) | Source of the Recent submenu. Display filters to folders that still exist; the saved list itself is never rewritten by a display. |

Dialog sizes are not persisted. Browse dialogs start from the field's folder, so no extra `last_dir` key is needed (**default**). Nothing else touches `QSettings` directly.
