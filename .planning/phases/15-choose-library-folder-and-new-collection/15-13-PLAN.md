<objective>
Close UAT gap 1 (blocker, WR-03 crash at exit) for the main window: a folder check that hangs on a dead network drive is never a live QThread when the interpreter shuts down.

Purpose: the automated UAT (test 8, runs s8 and s8b) crashed on exit with "QThread: Destroyed while thread '' is still running" and exit code 0xC0000409. The review fix WR-03/WR-04 parks still-running TaskWorker QThreads in a module list so they outlive the window; at interpreter shutdown that list is destroyed while the threads are still blocked in Path.is_dir() on the dead UNC path, and Qt aborts the process. A scratch probe this session reproduced it (a QThread blocked on an Event at exit gives 0xC0000409, stderr may even be empty) and showed the alternative (a daemon threading.Thread blocked the same way gives exit 0). The startup check already uses a daemon thread and UAT test 5 exited 0 with it blocked on a dead UNC path.

Design (chosen and justified here; plan 15-15 applies it to the three dialogs): a small runner `kicad_lib_manager/widgets/background.py` runs each check function on a `threading.Thread(daemon=True)`. The thread never touches Qt: it puts its outcome on a module-level `queue.SimpleQueue`. One module-level dispatcher QObject, created lazily on the GUI thread, owns a QTimer (POLL_MS = 15) that runs only while an outcome is outstanding, drains the queue and calls the callbacks on the GUI thread unless the task was cancelled. At exit the interpreter abandons a daemon thread that is still blocked, and no QThread object exists to be destroyed, so the abort cannot happen by construction. A signal emitted from the worker thread was rejected because it would touch a Qt object from a thread the interpreter is tearing down. Keeping QThreads alive past teardown (leaking them, or os._exit) was rejected: it relies on undocumented shutdown order or skips QSettings and atexit flushing.

Output: the runner module; main_window.py's switch check and Recent existence check on it, closeEvent cancelling instead of parking; a child-process exit test (modes switch and recent); runner unit tests; updated main-window tests.
</objective>
